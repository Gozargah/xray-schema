This option only takes effect on Linux and FreeBSD. The default is `false`.

When it is enabled, Xray points the system resolver at the TUN interface, so that the name lookups of the system go through Xray: on Linux, systemd-resolved (through `resolvectl`) at the first IPv4 address in `gateway` plus one (e.g. `10.0.0.1/16` → `10.0.0.2`), or without an IPv4 one, the first IPv6 address plus one (e.g. `fc00::1/64` → `fc00::2`); on FreeBSD, through `resolvconf(8)`, at the first IPv4 address in `gateway` itself (e.g. `10.0.0.1/16` → `10.0.0.1`), as the TUN interface has the next one there. Without `gateway`, Xray reports an error and does not start. It is not taken from `dns`, as the system would then query those servers directly, outside the TUN interface.

Queries to that address have to be answered by Xray, so a routing rule has to send port 53 of this inbound to a [DNS outbound](https://xtls.github.io/en/config/outbounds/dns.html). Xray checks this before changing the system DNS, and does not start if such a query would not reach a DNS outbound, or if Xray's own [DNS](https://xtls.github.io/en/config/dns.html) could resolve through the system resolver (no name servers, or a `localhost` one), which would loop.

On Linux, it needs systemd-resolved 240 or later to be running. On FreeBSD, `resolvconf` has to write the resolver files (no `resolvconf=NO`, nor `inclusive_interfaces` covering the TUN interface, in `resolvconf.conf`); with `local_unbound`, unbound's DNSSEC validation has to be turned off, as the extra queries of validation get no answer through the DNS outbound. Whenever the system DNS cannot be changed, Xray does not start. The setting is reverted when Xray exits normally; if Xray is killed (e.g. with `SIGKILL`), run `resolvectl revert <interface>` on Linux or `resolvconf -d <interface>` on FreeBSD to clean up.
